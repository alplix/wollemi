# EPS cards (design specification, draft v0)

Diagram: `electronics/eps_diagram.svg` (generated by `electronics/eps_diagram.py`). Numbers: `sim/eps_design.py`. Interfaces: `docs/electrical-interface.md`.
Floor plan: `electronics/gen_eps_card.py` places every function block below on the real 100 x 100 mm notched Wollemi card outline next to the WL-P connector (`electronics/kicad/wollemi_eps_card.kicad_pcb`
for EPS-A/EPS-B, `wollemi_survival_card.kicad_pcb` for the survival card), DRC clean. This proves the partition *physically fits* the card format; it is still a floor plan of labelled placeholder
blocks, **not a schematic** -- no part numbers are selected and nothing is routed. The parts named as candidates below are categories to be checked against datasheets.

## Partitioning

| Card | Function | Fed from |
|---|---|---|
| **EPS-A** | 3 buck MPPT channels, pack A charger and protection, ideal-diode output to bus A, telemetry MCU with CAN-FD | wing A (3 panels, 10s2p, ~24 W each) |
| **EPS-B** | identical to EPS-A | wing B |
| **Survival card** | pack C charger, direct string path to the supervisor (sun-only mode), two burn-wire drivers with three inhibits | dedicated body string (4s2p, ~9.6 V, 1 A) |

Each chain is electrically and physically independent (separate deck, separate vault). Loss of one EPS card removes half of the solar input and one battery bus only.

## Key requirements and values

| Item | Value | Basis |
|---|---|---|
| MPPT input window | 8 - 40 V | string Vmp 20.7 V hot, cold Voc 34.9 V (`eps_design.py`) |
| MPPT power per channel | 24 W in, ~4.6 A out at 5 V, efficiency >= 95 % | 10s2p panel |
| Battery bus | 5.0 - 7.3 V (2S LiFePO4), nominal 6.4 V | `docs/electrical-interface.md` |
| Charge current | CC-CV to 7.3 V, 3.3 A (C/2) per pack; **no charging below 0 C**; balancing | 26650 cells |
| Discharge protection | fuse + eFuse; trip 1.5x nominal | hardware only |
| OVP / UVP | 7.5 V / 4.6 V comparators independent of the MCU | hardware only |
| Output | ideal diode into the bus (OR-ing) | fault isolation |
| Telemetry | V, I, T per string and pack, over CAN-FD | protocol `hk_power` (`docs/protocol-messages.md`) |
| Survival path | string -> ideal diode -> supervisor, works with dead pack C | sun-only mode (AO-7 style) |
| Burn-wire drivers | 2 channels, three independent inhibits (timer, supervisor, separation switch) | launch-provider style requirement |
| Radiation | TID target 30 krad with the vault (`docs/longevity.md`); latch-up protected rails | COTS with mitigation |

## Candidate parts (v0 selection, real COTS parts against the values above; not yet ordered, verified or radiation-screened)

These replace the earlier generic categories with named parts chosen against real datasheet ranges. Nothing here is final: exact charge/OVP/UVP set-point resistors must be computed from each datasheet's own formula (not repeated here to avoid stating a value that has not been checked against the actual datasheet), and TID/latch-up data for most of these parts is not public and needs a vendor NDA or an independent test.

| Block (floor plan) | Candidate part | Why it fits | What still needs checking |
|---|---|---|---|
| `MPPT_BUCK` x3 (EPS-A/B) | **Analog Devices LT8490** buck-boost MPPT battery charger | VIN 6-80 V covers the panel string (20.7 V hot Vmp to 34.9 V cold Voc); VBAT 1.3-80 V covers the 5.0-7.3 V bus; built-in perturb-and-observe MPPT; CC-CV charge profile set by external resistors; thermistor input gives the "no charge below 0 C" cut-off in hardware, no MCU needed | LT8490's named chemistry presets are SLA/flooded/gel/Li-ion; LiFePO4 is not a named preset, so the CC-CV set-points (3.3 A, 7.3 V float per pack, per `docs/eps-card.md`) must be programmed manually per its resistor-programming formula, checked against the datasheet in hand. TID/SEL data not public. |
| `CHG_BAL` (EPS-A/B) | **TI BQ29209-Q1** 2-series cell automatic balance corrector + OV protection | Matches the pack exactly at 2S (most general-purpose balancer/monitor ICs, e.g. TI's BQ769x0 family, start at 3S and do not cover 2S); works with no host/MCU, matching "hardware-only protection"; the LT8490 units already do the pack-level CC-CV charging, so this device's job is narrowed to per-cell balance correction, which fits its actual function | Balancing current and correction time against our charge current and cycle count; confirm it does not conflict with LT8490's own float regulation. |
| `IDEAL_DIODE` (both cards) | **Analog Devices LTC4359** ideal diode controller (drives an external N-FET) | 4-80 V range covers the 5.0-7.3 V bus with margin; explicitly designed for ORing redundant supplies, which is exactly the A/B bus merge and the survival direct path | External FET R_DS(on) and thermal design once the bus current is pinned down; reverse-transient behaviour under a hard short on one chain. |
| `EFUSE_OVPUVP` (EPS-A/B) | **TI TPS2597x** eFuse, 2.7-23 V, 7 A, resistor-set OVP/UVP | Comfortably covers the 5.0-7.3 V bus and battery currents with margin; OVP/UVP thresholds set by resistor dividers, no MCU in the trip path, matching the hardware-only requirement | Exact trip-point resistors from the datasheet formula; inrush/current-limit behaviour into the ideal-diode stage ahead of it. |
| `TELEM_MCU` (EPS-A/B) | **STMicroelectronics STM32G0B1** (Cortex-M0+, integrated FDCAN) | Native CAN-FD peripheral (matches the CAN-FD control plane already in the architecture), low power, well below the STM32H7 flight controllers in cost and complexity since this is telemetry-only, not protection | This MCU is explicitly outside the protection path (telemetry only); its ADC front end (current-sense amps, thermistor dividers) is not yet designed. |
| `CHG_C` (survival card) | **LT8490 again** (parts commonality with EPS-A/B) | Pack C is now specified as 2S1P (`configs/12u_science.toml`, `docs/power-architecture.md`), matching the A/B bus convention on purpose so the same charger, ideal-diode and eFuse parts can be reused across all three chains -- fewer unique parts to qualify and stock | A ~780 mAh small-format LiFePO4 cell in this capacity class is not yet sourced; the charger set-points still need the datasheet-formula check noted above. |
| `DIRECT_PATH` (survival card) | LTC4359 (same as above) | Same ORing function, string straight to the supervisor, bypassing pack C when it is dead (AO-7-style sun-only mode) | As above. |
| `BURNWIRE1`/`BURNWIRE2` (survival card) | **Discrete circuit, not a single IC**: a logic-level N-channel MOSFET high-side switch, gate-enabled only through a **3-input AND gate** (e.g. a single-gate logic IC such as a 74LVC1G11) wired to the three inhibits (timer, supervisor GPIO, separation switch contact) in series, driving a nichrome wire | This is how CubeSat burn-wire releases are built in practice (a MOSFET switch plus a simple current-setting resistor, not a dedicated "burn-wire IC"); published designs use resistances around 8 ohm and currents around 1.6 A for a nichrome element of this class, which the actual wire and current must be sized against, not assumed | Confirms the "hardware-only, three independent inhibits" requirement directly: none of the three gating signals passes through an MCU that could itself be reprogrammed to enable the burn without all three. Wire gauge/resistance and drive current still need picking for the actual hardware. |
| `TELEM_MCU` (survival card) | **Open design question, not yet decided**: the floor plan places a second STM32G0B1 here, but the survival chain's own supervisor (MSP430FR, elsewhere in the architecture) already exists on this power path -- a simpler, more reliable design may read this card's telemetry directly into the supervisor's own ADC instead of adding a second MCU on the highest-reliability chain. Flagged for the next revision rather than decided here. | | |

None of the above has a confirmed radiation (TID/SEL) qualification; all are COTS parts chosen for spec fit only, consistent with the rest of the design (`docs/longevity.md`, radiation vault around the more critical control electronics).

## Verification (planned)

- Board-level: efficiency sweeps, thermal test, cold-start from a dead pack, fault injection (short on each output, open cell, reversed string).
- System-level (PWR-3): loss of packs A and B leaves supervisor and beacon running from the survival string.
- Environmental: thermal cycling with the modelled temperature swings (`docs/thermal.md`), radiation screening of the controllers.
