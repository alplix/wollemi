# Ginkgo completion plan (living document)

Goal: bring the satellite design to a complete, verified, documented state ("design freeze candidate v0") before deciding on hardware. Ground kit, sponsor material and
manufacturing come after. Status boxes are updated as work is finished; `docs/status.md` is regenerated by `python tools/check_all.py`.

## Already done (before this plan)

- [x] Requirements draft, architecture, power/propulsion/longevity/data docs, tiered configs (`configs/`)
- [x] Parametric CAD (voxel packing, build123d assembly, interference check, mass properties, STEP/STL/renders)
- [x] Layout rules as code, balance, data budget, longevity, link budget, ADCS sizing, thermal model
- [x] Protocol specification with generated C/Python code and cross-language tests
- [x] Electrical interface, KiCad card template and backplane strip (DRC clean), EPS card specification
- [x] Firmware core (auth, modes, FDIR, command queue, OTA) with Ed25519 cross-checks
- [x] Live verification matrix (`sim/trace_check.py`), risk register, prior-art review, OreSat decision, outreach LED package

## Rules for this run

- Work only inside the private repository; nothing is published, no accounts, no purchases.
- Every analysis states its assumptions and limits; numbers are engineering estimates unless a source is cited.
- A failing check is reported, never hidden; design changes found by analysis are written down with the reason.
- Every step ends with tests or checks run and a commit to the private repository.

## Decisions waiting for the operator (do not block the plan)

1. Mission target: flight mission, flight-quality reference design, or balloon/FlatSat first step (drives effort and cost).
2. Launch orbit preference (dawn-dusk sun-synchronous is favoured thermally and for power).
3. Whether the outreach LED flasher stays in the flight configuration.
4. Public release timing and licences (CERN-OHL-S-2.0 / Apache-2.0 / CC-BY-4.0 planned).
